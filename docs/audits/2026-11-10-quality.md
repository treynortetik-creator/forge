## `scripts/validate.sh`

```

```

Stdlib Python inside a bash wrapper; uses PyYAML for frontmatter if present, a minimal parser otherwise.
Exits 1 on any failure. Current run: `5 plugins, 29 skills, 4 commands: 0 failure(s), 3 warning(s)`
(the three zsh scripts). With `--smoke`: 6 warnings (those three plus python-pptx ×2 and pronouncing, all
optional deps). Verified it catches a wrong skill name, a dead `${CLAUDE_PLUGIN_ROOT}` path and a `/Users/…`
path by injecting each and reverting.

## Judgment calls — not changed

### Trigger overlap between skills

| Skills | Overlap | Severity |
|---|---|---|
| `dossier-to-outline` vs `dossier-to-characters` + `dossier-to-worldbuilding` + `outline-generator` | `dossier-to-outline` says it builds the character bible, worldbuilding sheet **and** chapter outline, and triggers on "generate characters and worldbuilding". Each of those has its own dedicated skill. "Build the cast" or "build my outline" can land on either. Suggest: make `dossier-to-outline` an orchestrator that calls the other three, or narrow its triggers. | high |
| `braindump-to-dossier` vs `short-story-dossier` | Both start "Use when you have a raw story idea". The short one is distinguished only by "short-story" in its triggers; a bare "turn my idea into a story plan" is ambiguous. | medium |
| `art-department` vs `deck-builder`, `design-audit`, `music-video`, `scroll-film-studio` | art-department triggers on bare "design", "slide", "video", "visual", "render". It is meant as a playbook loaded alongside the others, but its triggers are broad enough to pre-empt them. | medium |
| `design-audit` vs `deck-audit` | "check the design" / "is this accessible" vs "reviewing, checking or QA-ing a deck". Distinguishable by artifact type (rendered page vs .pptx), usually fine. | low |
| `render-diff` vs `track-check` | Both "compare" audio; render-diff is null-test identity, track-check is musical/singer comparison. Descriptions already separate them. | low |
| `story-hacker` vs `short-story-hacker` vs `/hack` | Already cross-referenced ("use short-story-hacker for short fiction"). | low |
| `logic-check` vs `outline-generator` | outline-generator includes its own logic check. Intentional. | low |

### Other

1. **Author name is inconsistent**: deck-forge and proof-forge `plugin.json` use `"treynortetik-creator"`; everything else uses the full name. Pick one.
2. **deck-forge and proof-forge have no README, LICENSE or `displayName`**; design-forge `plugin.json` has no `homepage`/`repository`. The root LICENSE covers the repo, but plugins installed alone carry no licence file.
3. **Docs drift**: `story-forge/README.md` does not mention `clean-export`, `dossier-to-characters` or `dossier-to-worldbuilding`.
4. **Personal name in content**: `story-forge/references/writing/anti-slop.md` headings "Treynor's law (2026-07-16)". Harmless if intended; flag only because the audit asked about personal data.
5. **macOS-leaning defaults**: three scroll-film-studio scripts are `#!/bin/zsh` (zsh is not on many Linux installs; `continuity-gate.sh` uses zsh-only `<->` so it cannot just be run with bash); `photo-to-3d-loop` defaults `P23D_FONT` to a `/System/Library` path (overridable by env); `install.sh --tools` uses Homebrew. All work on Linux with setup, none are broken.
6. **`book-summarizer` description** ends "Replaces the n8n 'Book to Summary+' automation", which is history, not a trigger. Could be cut.
7. **`kie-chain.py`** reads its API key at import time from `KIE_API_KEY` or `~/.config/kie/key`. Fine, but key loading inside `main()` would be cleaner.
